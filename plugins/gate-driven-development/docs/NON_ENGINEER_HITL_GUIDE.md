# 非エンジニア承認者向け HITL ガイド

> **対象**: PM / PO / 業務担当 / レビュワーなど、実装コードを読まないが GDD の人間確認に参加する人
> **目的**: human check で「何を見て OK するか」「何を差し戻すか」を短時間で判断できるようにする
> **上位正本**: `references/human-check-template.md`

---

## まず知っておくこと

GDD の human check は、コードレビューではなく **方向性の承認** です。見るべきものは「何を作るか」「どこまで作るか」「OK 後に AI がどこまで自走するか」です。

実装方法の細部や内部 state は、原則としてエンジニアと AI reviewer が確認します。非エンジニア承認者は、できあがりや業務上の期待がズレていないかを見る役割です。

エンジニア向けの HITL でも、専門用語だけで説明しない方針です。先にやさしい日本語で意味を説明し、`Approved Direction` や `Human Check Questions` のような内部名は括弧で補足します。読んでいて「何を言っているのかわからない」と感じたら、無理に OK せず `判断材料が足りない。もっとやさしく説明して` と返してください。

---

## 30秒判断

human check が出たら、最初に以下だけ見ます。

0. **どこまで自走するか**（OK すると AI がどこまで進むか）
   - OK すると AI は先に進みます。作るもの、作り方、確認範囲、AIに任せる範囲に違和感がないかを見ます。
1. **何を作るか**
   - 作るもの、完了条件、採用する技術スタックが期待と合っているかを見ます。
2. **OKでも許可されないこと**
   - merge、deploy、本番操作、外部投稿が OK に含まれていないかを見ます。
3. **人間に戻す条件**
   - 危険操作や本番相当 write で AI が止まって戻ってくるかを見ます。
4. 差し戻すときの返し方（**これは HITL の欄ではありません**）
   - `1 は ... に変更` のように、番号で差し戻します。

その後、必要なら **採用しない案**（一次表示以外では **却下した代替案**）を見ます。ここには「最初に話した内容から何が変わったか」「なぜ変えたか」「OKすると何が進むか」が短く出ます。ここで違和感がある場合は、詳細表を読み込むより先に `判断材料が足りない` または `N は ... に変更` と返してください。

---

## OKしてよい条件

- 「何を作るか」が期待と合っている
- 「やらないこと」が期待と合っている
- 完了条件が、業務上の確認ポイントとして納得できる
- OK 後に AI が進める範囲が広すぎない
- deploy / 本番操作 / 外部投稿などが、この OK だけで実行されない

迷う場合は、無理に OK せず `判断材料が足りない` と返してください。

---

## 差し戻す条件

- 作るものが思っていたものと違う
- 完了条件が曖昧で、できあがりを判断できない
- 「今回はやらないこと」に、本当は必要なものが入っている
- 採用する技術スタックや外部サービスの使い方が期待と違う
- OK 後に AI が進める範囲が広すぎる

```

```

## 読まなくてよいもの

初回判断では、以下は読まなくてよいです。

- `.steering/` の全文
- `state.md` の内部値
- `tasklist.md` の細かいタスク一覧
- reviewer の全ログ
- テストコマンドの詳細

ただし、判断に迷った場合はエンジニアに `requirements.md` の該当箇所だけ確認してもらってください。

## 非エンジニア承認者が見るべき欄

> 欄名は HITL テンプレートの見出しと同じ語を使う。一次表示は `references/human-check-template-compact.md`、詳細表は `references/human-check-template.md` が正本。

| 欄 | 見る理由 |
|---|---|
| 判断ポイント（詳細表では 30秒判断） | OK で何が決まるかを最短で確認する |
| ズレ確認 | ズレると手戻りが大きい箇所だけを見る |
| 採用しない案（詳細表では 却下した代替案） | 最初に話した内容と、OK する内容がズレていないかを見る |
| 完了条件の変換 | 最初の依頼がテスト可能な条件にどう変わったかを見る |
| どこまで自走するか（OKで進む範囲 / OKでも許可されないこと / 人間に戻す条件） | OK 後に AI が進める範囲、OK でも実行されないこと、止まって人間に戻す条件を確認する |
| どう確かめるか（検証する方法・内容） | 何を検証済みとして扱うか、何は未確認のまま残るかを見る |
| まだ確認できないこと | 未検証のまま残るものを把握する |

---

## エンジニアに確認した方がよいサイン

- 技術スタック、credential、tenant、AWS account、外部サービス連携の話が出ている
- 本番相当の検証、E2E、外部投稿、deploy が関係する
- セキュリティ、個人情報、権限、監査ログが関係する
- 「非スコープ」に入っているものが、本当に不要か判断できない

この場合は、承認者だけで判断せず `判断材料が足りない` と返すのが安全です。
