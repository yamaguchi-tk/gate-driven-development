# 非エンジニア承認者向け配布文

> **対象**: PM / PO / 業務担当など、GDD の human check で OK / 差し戻しを判断する人
> **目的**: GDD を自分で導入・操作しなくても、承認時に何を見ればよいかだけを 1 ページで共有する
> **詳しい読み方**: `docs/NON_ENGINEER_HITL_GUIDE.md`

---

## 何をお願いしたいか

GDD では、AI が実装を始める前に **human check** という確認画面を出します。非エンジニア承認者には、コードや内部ログではなく、次の 3 点を見てほしいです。

1. 作るものが期待と合っているか
2. 完了条件が業務上の確認ポイントとして納得できるか
3. OK 後に AI がどこまで自走してよいかが広すぎないか

---

## 最初に見る欄

human check が出たら、まず以下だけ見てください。

- `判断ポイント`
- `ズレ確認`
- `どこまで自走するか`（`OKで進む範囲`）
- `OKでも許可されないこと`
- `まだ確認できないこと`（詳細表にのみ出ます）

`.steering/`、`state.md`、`tasklist.md`、テストコマンドの詳細は初回判断では読まなくてよいです。

---

## 返答のしかた

問題なければ:

```text
OK
```

直したい点がある場合:

```text
1 は画面表示まで含めてください
```

判断できない場合:

```text
判断材料が足りない。ユーザー影響とリリース後の確認方法を追加してください
```

大きくズレている場合:

```text
全面見直し。作るものが業務フローと合っていません
```

---

## OK だけでは実行されないこと

通常の human check で `OK` と返しても、以下は勝手に実行されません。

- merge
- 本番 deploy
- terraform apply
- AWS write 操作
- DB write / Docker push
- 外部投稿

これらが必要になった場合は、AI が別途確認します。

---

## エンジニアに確認した方がよいとき

以下が出てきたら、無理に OK せず `判断材料が足りない` と返してください。

- credential / tenant / AWS account / 外部サービス連携
- 本番相当の検証、E2E、deploy
- 個人情報、権限、監査ログ、セキュリティ
- 「今回はやらないこと」に、本当に必要そうなものが入っている

---

## 導入担当者へ

この文書は **承認だけ担当する人向け** です。GDD のセットアップや運用手順は、導入担当エンジニア / テックリードが `docs/ONBOARDING.md` と `docs/PROJECT_CLAUDE_MD_TEMPLATE.md` を読んで対応してください。
