#### Summary

`references/subagent-dispatch.md` の 6 つの Agent Template（planning・design-gating・task-breakdown・TDD・implementation-gating・completion-check）に `subagent_type` を足し、subagent が読む対象を呼び出し側が埋める欄（`## 読む対象`）を足した（X-80 提案 1）。

2026-09-20 の実測（GDD を使う別の repo の 2026-09-01 以降の GDD セッション 30 本）で、総額の 40% が `subagent_type` 未指定の subagent だった。Agent 呼び出し 333 回のうち 168 回が未指定で、prompt はどれも「`skills/<phase>/SKILL.md` を読んで phase を実行」の Template だった。`Agent` ツールは `effort` を引数で受けないため、task-breakdown・TDD の Template にあった `effort="medium"` は効いておらず、effort を固定できるのは agent 定義の frontmatter だけである。

phase の観点・gate の判定・State Update Contract・Return Contract・Worktree Binding Precheck・Post-Return Routing・実装漏れ防止 guard は変えていない。Template の中でこれらの本文は動かしておらず、欄をその手前に足しただけである。変わるのは、gate subagent が読む範囲を呼び出し側の欄が起点として渡す点（SKILL.md が名指し・要求した読み取りは場所を問わず引き続き読める）と、対象の差分の範囲を呼び出し側が渡し、runner が tip（`rev-parse HEAD` の実測）と base（起点）を照合する点である。completion-check の起点は `state.md` をディスクから読んだ値と照合する。
