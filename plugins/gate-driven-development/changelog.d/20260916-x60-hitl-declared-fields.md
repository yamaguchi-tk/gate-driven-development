#### Known limitations

- **Opus 指摘 H-3（placeholder の角括弧だけを取り除いた回答が合格しうる）はこの再設計で閉じた**。旧実装の `_is_substantial()`（12文字以上の可視テキストで「実質的な内容」とみなす長さヒューリスティック）自体をこの再設計では撤去したため、H-3 が突いていた「角括弧除去で閾値を超えさせるバイパス」は検証対象自体が存在せず再現しえない（`BodyContentIrrelevantToVerdictRegressionTests.test_valid_tag_passes_even_with_untouched_looking_body` で固定。この regression test 自身が「タグさえ正しければ本文の内容は一切見ない」ことも同時に示している——これは意図した設計であり副作用ではない）
- **宣言値そのものの真偽は検証しない**。`<gdd-hitl-fields options="filled" ...>` と宣言しても、実際に `選択肢の説明` 節に Option A/B が書かれているかは機械検査しない（X-53 の `承認ポイント数: <N>` と同じ、他の固定フィールドと同じ自己申告の信頼境界）。これは PR 旧#92 の raw-text-match 方式が持っていた「Option ラベルを2個以上実際に数える」チェックからの意図的なスコープ縮小である——raw-text-match-vs-placeholder クラスタが4巡連続で再発した根本原因は「本文中の文字列一致で意図を推定しようとしたこと」自体にあり、この再設計はその推定を完全にやめて宣言に置き換える方針を取った。この意味で本文の真正性検証は、承認者が実際の本文を読んで宣言と食い違っていないか目視確認する前提に依存する
- 同じ理由で、旧実装が持っていた「Option ラベルが選択肢の説明節内でのみカウントされる」「ズレ確認の0件時の定型句 `延期・削除: なし` を受理する」等の本文レベルの許容ルールは、対応するチェック自体が無くなったため意味を持たなくなった（本文を全く見ないため、これらの許容判断そのものが不要になった）
- タグ内の属性値に引用符無しの `>` が混入する等でタグ境界の正規表現が本来より手前で切れた場合、実際には何かが書かれていても「属性自体がありません」という不正確なエラーメッセージになる（独立レビュー finding、実機で再現確認済み）。fail 方向自体は安全側（reject）のため機能上の欠陥ではないが、診断メッセージの精度は保証しない。closed-form（自由文の内容は一切解釈しない）という設計方針どおりの意図的な限界として受け入れる
- 同一のスタンドアロンタグ行内で同じ属性が複数回書かれた場合、`dict()` の構築上、後に書かれた値が採用される（例: `options="none" options="filled" ...`）。重複自体を検査対象にしていないため、どちらが「正しい」自己申告かは検査できない（PR レビュー finding、Low、advisory。本 PR のスコープでは対応しない）
- **（PR後-2対応で更新）位置契約への再設計により、フェンス種別・HTMLコメント・インデントコードブロックの構文列挙に関する限界（旧: CommonMark 3種の網羅を最終防衛線とする、HTMLコメントの同一行複数マーカー等）は撤廃した**。構文の種類を一切見ないため、未列挙の構文（今回発見された info string 付き閉じ行・同一行のコメント再オープン・`<pre>`/`<textarea>` を含む）による再発クラスは構造的に無くなった
- **位置契約の意図的な境界**: フェンス・HTMLコメント・`<pre>` 等の中に**タグと `<gdd-stop>` のペアが完結して**いる場合、そのペア自体は構文を見ないため合格しうる（閉じているかどうかは無関係）。**（PR後-3対応で更新）** ただし universal quantification（全 occurrence を検査）により、それが「本物」の代わりになることはない——文書中の別の `<gdd-stop>` occurrence（例えば実際にテンプレートどおり出力の末尾にある本物）はそのペアとは独立に検査される。逆に、タグの後に説明文などを挟んでからマーカーを出す（テンプレートどおりマーカー直前に置かない）と、正しい宣言でも無視される
