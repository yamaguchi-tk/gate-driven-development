# 判断の委任（相談役に判断させる手順）

> **所有**: 本人が判断を委任した human check を相談役が判断する手順、相談役と human check が使う比較の軸の扱いと根拠
> **参照元**: `agents/gdd-opus-advisor.md`・`gdd-opus-advisor-max.md`・`gdd-fable-advisor.md`（相談役）、`references/fixed-models.md`（相談役の段落）、`references/human-check-template.md` § 事前回答（いつ委任するか・記録・人に戻す条件の正本）、`references/state-machine.md` § Stop hook の判定順序（rule 2。§ 限界）

本人がタスクごとに「どこまで自走するか」と並べて選ぶ判断の委任（`references/human-check-template.md` § 自走上限の置換値の「判断の委任」、§ 事前回答）で、委任先が `opus`・`fable`・`並行` のとき、この手順で相談役に判断させる。いつ委任が効くか、記録の行、人に戻す条件は § 事前回答が正本である。repo 単位の宣言（旧 `GDD Autonomy: internal`・`GDD Autonomy Advisor`）は廃止した。`.gdd-config.md` にこの行があっても読まない。

## 判断の手順
1. 人間に見せるはずだった材料（human-check テンプレート、Handoff の材料）をもとに、委任先の相談役を起動する。Claude Code では Agent tool を、`opus` なら `subagent_type: gate-driven-development:gdd-opus-advisor`、`fable` なら `gate-driven-development:gdd-fable-advisor`、`並行` なら `gdd-opus-advisor` を同じ材料で並行に 2 本、`model` を渡さずに起動する（model・effort・read-only のツールは agent 定義で固定する。`model` を渡すと定義の model より優先される）。定義が読み込まれていないとき（plugin を更新する前から動いているセッション）は、`subagent_type: Plan`（Edit・Write を持たない）を `model: opus`（Fable の側は `model: fable`）で起動して定義の本文を prompt に渡し、記録の行の `model:` の欄を `<実際の model ID>（effort: main から継承）` と書く。Codex・Cursor では `references/fixed-models.md` の `general_heavy_risk` tier の別コンテキストを起動する（`並行` なら同じ材料で 2 つ。Fable は起動できないものとする）。SendMessage は使わない（直近の発言が別セッションになると、`hooks/scripts/validate-steering-write.py` の peer turn 検査が `approved` の書き込みを拒否する）。起動できない側があるとき（Codex で委譲の許可が無い、起動に失敗した。`fable` を `opus` に替えない。`並行` で片方だけ起動できたときも）は人間に止まる
2. 材料は要約せず場所で渡す。人間に見せるはずだった確認の文面をそのまま書いたファイル（`human-check-template.md` 一次表示の原則 7 の `human-check-draft.md`。Handoff ならその材料）のパスと、steering のパス（`requirements.md`・`design.md`・`state.md`・`worklog.md`）と、依頼の原文（`request.md`。無い・not-copied のときはその旨の 1 行）のパスを渡す。依頼の原文から、そもそもどうあるべきかを先に問い（確認の中の案は参考）、そのうえで「承認するか・どの案を採るか・人間に止めるべきか」を問う。止めるべきかの基準は `human-check-template.md` § 事前回答 3 の人に戻す条件（承認した要件を満たせない、または満たさない方向に変えるか）で、その節の場所も渡す。security boundary に触れる変更では、信頼境界と fail-closed の観点を足す。相談役はファイルを書き換えず、記録は main が行う
3. 相談役が「人間に止めるべき」（`止めるべきか: yes`）と答えたら止まる。`並行` では、どちらかが止めるべきと答えたとき、または 2 本の推奨する案が違うときも止まる（委任を選んだ本人が割れを見ていないので、main が割れを決めない）。相談役の推奨する案が確認に並んだ案のどれでもないとき（案に足す・変える推奨を含む）は、依頼の範囲の中の分をその案で決め、依頼より広げる分は採らずに `範囲を広げる提案` として残す（止まるのは、その案が § 事前回答 3 の人に戻す条件に当たるときだけ。手順 4）。それ以外も相談役の推奨（`並行` では 2 本が一致した案）で決める
4. 採る案が § 事前回答 3 の人に戻す条件に当たるときも止まる。それ以外の承認と記録は § 事前回答 2 のとおりに行う
5. `<gdd-stop reason="human-check-waiting">` を出さずに続ける

## 比較の軸
相談役の出力の `比較の軸:` と、human check の判断ポイントの `判断軸:` は、同じ 6 軸（要件の充足度、信頼境界・fail-closed、確かめやすさ、堅牢性、保守性、費用）を使う。軸は読み手に直接書く（相談役の `agents/gdd-opus-advisor.md`・`gdd-opus-advisor-max.md`・`gdd-fable-advisor.md` の `比較の軸:` には名前と定義を、human check の `references/human-check-template-compact.md` の `判断軸:` には名前を）。ほかの repo の相談役と human check の書き手は、この文書を読めないことがあるため。軸を変えるときは、この 4 か所と本節の、計 5 か所をそろえる。human check の `判断軸:` には決め手の軸と一言だけを書き（推奨案が要件の充足度か信頼境界・fail-closed で ○ でなければ、その軸も書く）、案ごと・軸ごとの ○/△/× は相談役の出力か `requirements.md` の詳細比較に置く（一次表示の行数の上限に当たらないように）。要件の充足度と信頼境界は `対象外` にしない（2026-10-10 の事例では、保守性・堅牢性だけで比べ直した推奨が信頼境界を弱める案に寄り、auto mode の判定器に止められた）。軸は、相談役の回答で推奨の根拠に出た観点の多さを見て決めた（多い順に、確かめやすさ、要件、信頼境界、波及、保守性、費用、堅牢性、可逆性）。堅牢性は堅牢性と波及を、費用は費用と可逆性を合わせた軸で、既存の規約との揃いは保守性に、範囲の広さは要件の充足度に、誤 block は信頼境界に含めた。
## 限界
- human check について Stop hook が押し返すのは、bind 済み steering の `state.md` の `判断の委任` の欄がちょうど 1 つで値が `fable`・`opus`・`並行` のどれか（欄があればこれだけで決め、`人に止める`・読めない値・2 つ以上なら押し返さない）、または欄が無く `worklog.md` の最後の `事前回答:` 行の `委任先` が `fable`・`opus`・`並行`・`なし` のどれかなのに、`human-check-waiting` で止まったときだけである（`hooks/scripts/lib/autonomy_pushback.py`。同じ記録のまま 2 回目に止まったら通す。マージ待ちの押し返しは `references/post-merge-qa.md` 手順 2）。人に戻す条件の判定と記録の行は main の手順だけで守らせ、compaction や resume の後は従来どおり止まることがある（止まる側に倒れる）
- `並行` は 2 本が割れたら止まるので、割れる割合が高いと、委任を選んでも人に戻る回数が減らない。割れる割合は未測である
- Fable は `references/fixed-models.md` の tier に無く、`agents/gdd-fable-advisor.md` の `model: fable` を受け付けるかは環境ごとに未検証である（2026-10-04 に、Claude Code の `--plugin-dir` で読み込んだこの定義が fable・medium で動いた。ほかの版・環境では未測）。Codex・Cursor では Fable を起動できないので、`fable` の委任は人間に止まる。dispatch model gate（`hooks/scripts/lib/agent_dispatch_gate.py`。warn のみで block はしない）は、Opus の相談役を `model` 省略の起動だけ工程の model 検査から外し、工程を特定できる起動（`Resume From` が planning の工程か、3 gate 承認済みの `Next Action` が build の工程のとき）では、opus 以外の `model` を明示した起動を、工程の tier によらず `model` を省略するよう警告する。human check の表示点（事前回答の委任）は `Resume From`・`Next Action` が `human-check-waiting` なので判定しない。Fable の相談役と代わりの経路の `Plan` は、`model` の値によらず外すので、`gdd-fable-advisor` に `model` を渡して定義を上書きしても警告しない。相談の回数に上限は無い
