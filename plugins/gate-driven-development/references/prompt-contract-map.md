# GDD Prompt Contract Map

This map is the source index for GDD prompt guardrails. Use it when changing a
GDD skill, reference prompt, lint, replay fixture, or HITL template.

## How to Read This Map

- `Accident`: what went wrong in a real or plausible workflow.
- `Prompt owner`: the skill or reference that tells the agent what to do.
- `Executable guard`: lint, test, hook, or replay fixture that catches drift.
- `Good sample`: where the expected shape is fixed.
- `Residual risk`: what is still mostly judgment-based.

If a prompt change adds a new accident class, update this map before calling the
change complete.

## Prompt Refactoring Rules

1. Keep `description` as a routing contract, not a compressed workflow.
2. Put detailed procedure in the body or a reference document.
3. If a skill can be invoked manually only inside active GDD, say that in the
   description.
4. If a helper mutates artifacts, do not classify it as Lookup / Reference.
5. Every high-risk prompt rule should have at least one executable guard or a
   named residual risk in this map.
